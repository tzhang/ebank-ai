## 一、总体目标与成功指标

### v1 现状

- 纯静态内容站:文章(LLM / Harness)、技能库(Skills & MCP)、社区页,数据全部写死于 `src/lib/data.ts`;
- 社区页的「发起话题」按钮与话题列表均为 mock,无任何用户系统;
- 无后端、无数据库,Vercel Git 集成自动部署。

### v2 定位

从「金融 AI 内容平台」升级为「**内容 + 社区 + 智能体应用**」的用户平台。
Epic 1 解决「有真人」:注册、身份、真实的发帖与管理;Epic 2 解决「有产品」:把量化机构的研发流水线装进人人可用的界面,形成内容引流 → 应用留存 → 社区沉淀的闭环。

### 成功指标(建议基线,上线后校准)

| 指标 | 说明 | 建议基线 |
| --- | --- | --- |
| 注册用户数与发帖转化 | 新用户注册后 30 天内发起话题或回复的比例 | ≥ 10% |
| 工作坊会话完成率 | 从输入投资想法到产出回测报告的会话完成比例 | ≥ 60% |
| 因子被 fork / 分享率 | 产出因子被本人分享或他人 fork 的比例 | ≥ 15% |

> 数字不是验收标准,方向是。

## 三、Epic 2 · 投资策略与因子工作坊

### 定位红线(不可妥协)

- 产品定位是**研究与教育工具**,不是投资建议:输出因子与策略的统计验证结果,不输出个股买卖信号;
- 全站与报告页显著位置展示风险提示与免责声明;报告标注「AI 生成」(《人工智能生成合成内容标识办法》已于 2025 年 9 月施行);
- 不做实盘交易接入——v3 及以后也需要牌照前提,当前版本不设计任何下单能力;
- 回测口径(股票池、区间、费用、停牌与涨跌停处理)全部公开明示——可信度是这个产品的生命线。

### 理念:把 RD-Agent 的研发闭环装进普通人可用的界面

微软开源的 [RD-Agent](https://github.com/microsoft/RD-Agent)(Apache-2.0,pip 最新 0.8.0)在量化场景已经跑通这条研发闭环:其 RD-Agent(Q) 自称「首个以数据为中心的量化多智能体框架」(论文已收录 NeurIPS 2025,arXiv:2505.15155)——Agent 阅读已有因子库与数据描述,提出带经济逻辑的新因子假设,自动实现因子代码、经 Qlib 回测验证、归因分析,再带着反馈进入下一轮,因子随迭代沉淀入库;进阶版本还支持「因子进化」与「模型进化」交替执行(`fin_factor` / `fin_model` / `fin_quant`),官方披露在真实市场以不到 $10 的成本实现约基准因子库 2 倍的 ARR、且因子数少 70%+。这正是量化私募的研究流水线。

本 Epic 的产品化命题:**同样的闭环,换成普通人的一句话输入和看得懂的报告输出。**

```
                    ┌────────────────────────────────────────────┐
                    │            迭代进化 · 每轮基于回测反馈提出新假设          │
                    └────────────────────────────────────────────┘
                          ↓                                    ↑
    投资想法(自然语言) → 假设生成(Spec · 用户确认) → 因子实现(Implement · 代码可见)
                          → 回测实验(Experiment · Qlib) → 归因反馈(Analyze · 报告)
                                                                  ↓
        个人因子库 —— 成功因子沉淀入库:可复用 · 可分享 · 供下一轮假设参考
```

### MVP 用户旅程(单轮)

1. **描述投资直觉** — 「我觉得低换手率、研发投入又高的公司,长期会跑赢」——不需要任何量化术语。
2. **确认假设卡片** — Agent 把想法拆成可检验的假设:变量、方向、经济逻辑、灵感来源;用户可确认、修改或否决。
3. **查看因子代码** — 生成因子实现,代码可展开查看,附逐行通俗注释——透明可审计本身就是教育价值。
4. **一键回测** — 默认场景:沪深 300 或中证 500 股票池、近 5 年、月度调仓;高级面板可调参数。
5. **读懂报告** — IC / ICIR、分组收益、多空净值、最大回撤——每个指标配一句「这是什么、怎么看」。
6. **一键迭代** — Agent 基于回测反馈提出改进假设,进入下一轮;进化树可回溯任意版本。

### ARCH · 技术架构

回测是分钟级长任务,Vercel 的 Serverless 不适合承载,因此采用**双服务架构**:Next.js 前台留在 Vercel,独立的 Python Agent 服务负责研发闭环与回测队列。注意 RD-Agent 官方仅支持 Linux + Docker 运行——Agent 服务需落在 Linux 主机,与 D4 的基础设施选址联动。

```
ebank.ai 前台(Next.js · Vercel)            Agent 服务(Python · RD-Agent + Qlib)
用户 · 会话 · 论坛 · 报告展示  ←──任务提交/SSE 进度──→  长任务队列 · 独立部署
                                                     ↕ 行情读写 · 因子存取
                                              数据层(A股行情 AKShare/Tushare ·
                                              Postgres · Parquet 落地)
```

**回测引擎三选一:**

| 方案 | 做法 | 优势 | 代价与风险 |
| --- | --- | --- | --- |
| **A · 封装 RD-Agent**(建议起步) | Agent 服务运行 RD-Agent 0.8.0(pip 安装,Linux + Docker 环境),前台经 API 提交任务、收取结果;`server_ui` 提供实时 trace 接口可评估复用 | 因子 / 模型 / 联合进化三种闭环与 Qlib 回测开箱即用;官方 Web UI 与 live demo 可作产品原型参照 | 仅支持 Linux + Docker,部署偏重;深度定制需要读它的源码 |
| B · Qlib 自研编排 | 自建 Agent 编排,Qlib 只做回测引擎 | 编排可控,UI 与产品逻辑贴合度高 | Agent 闭环全部自研,M2 工期约 +2–3 周 |
| C · 自建轻量引擎 | AKShare 数据 + 自研向量化回测,不依赖 Qlib | 最轻、最省钱,口径完全自主 | 「与量化机构同等能力」叙事打折,指标口径需自证 |

> 建议:A 起步最快验证价值,同时保留 C 作为降级路径——A 与 Qlib 口径绑定的完整回测可留给付费档,C 的轻量回测可作免费档模式。

### LLM 与数据策略

- **模型接入**:OpenAI-compatible 网关(LiteLLM 或同类),可切换 DeepSeek / Qwen / GPT 系——RD-Agent 官方已默认 LiteLLM 后端并实验性支持 DeepSeek 官方 API,与我们的路线一致,可省去自建适配;
- **模型分级**:假设生成与归因分析用强模型,格式化与常规步骤用轻量模型;单会话 token 预算 + 超限降级;
- **数据源**:A 股日频,AKShare(免费)起步,Tushare Pro / 聚宽按需升级;日线落地 Postgres / Parquet,盘后定时更新。

## 五、里程碑与交付节奏

从纯静态站到「全栈 + AI 服务」跨度很大,里程碑必须强分段:M1 不碰工作坊,每期独立可上线。

| 里程碑 | 周期 | 交付范围 | 出口标准(DoD) |
| --- | --- | --- | --- |
| **M1** | 4–6 周 | INF 全部 + AUTH / PROF / ADM / FRM 的 P0 项 | 注册 → 登录 → 发帖 → 管理闭环全流程可用;未登录可浏览;管理后台最小版上线 |
| **M2** | 6–8 周 | WORK-201 ~ 208;双服务架构与数据落地 | 新用户 10 分钟内从想法到回测报告;回测 P95 ≤ 5 分钟;单轮会话成本可控 |
| **M3** | 约 4 周 | 迭代进化完善 + WORK-210 ~ 213;ADM-123 / 124 | 因子广场含 ≥ 20 个官方种子因子;因子卡片可在话题页正常渲染 |
| **M4** | 机动 | WORK-220 ~ 223(模型工作坊、组合回测、日报、模拟盘) | 由 M2 / M3 的留存与付费意愿数据决定范围,不提前承诺 |
